Trust & safety

Security & Privacy Centre

MKULIMA is being built with safer defaults. No website can promise complete protection from every attacker; security also depends on secure accounts, hosting configuration, payment-provider controls and ongoing maintenance.

Protection measures configured for this static website

Browser security headersNetlify-compatible rules set a Content Security Policy, prevent framing, reduce MIME sniffing and set a safer referrer policy.
HTTPS upgradeRequests are directed toward secure transport and HSTS is requested for supported browsers.
Restricted browser permissionsCamera and microphone are limited to this origin; location, payments and USB permissions are disabled by policy.
Safer local data handlingForms validate expected values and show when information is stored only on this device. Local storage is not encrypted account storage.

Important protections not yet implemented or activated

CONFIGURATION REQUIRED

The repository now contains a subscription backend and account centre. Code being present is not proof that a provider is configured or that a real payment has succeeded. The subscription setup checklist is stored in the project repository as SUBSCRIPTION_SETUP.md.

  • Multi-factor authentication, identity verification and production account security hardening. A Supabase account sign-in flow has been added, but it is not operational until the owner configures Supabase and verifies the deployed functions.
  • Server-side authorisation, secure cloud database and account recovery.
  • Server-enforced 72-hour trials, paid-plan entitlements and anti-abuse rate limits.
  • Live Safaricom Daraja processing and subscription activation are not operational until the owner configures Supabase, runs the subscription SQL, adds valid Daraja credentials in Netlify, confirms the registered shortcode/payee, and passes end-to-end sandbox tests.
  • Central security monitoring, alerting, private vulnerability reporting and independent penetration testing.

Do not store passwords, M-Pesa PINs, card details, identity documents or other secrets in MKULIMA's local notes. Never share a one-time code with anyone.

How to keep your farm data safer

  • Use a screen lock and keep Android and your browser updated.
  • Do not use shared phones for sensitive records unless you can protect and remove local data safely.
  • Download backups only to a device you trust; a JSON backup may contain personal farm information.
  • Verify the payee and amount on the official M-Pesa confirmation screen before approving any payment.
  • For a suspected security issue, do not post passwords, personal data or a working exploit publicly. A dedicated private security contact still needs to be configured by the operator.

Our security commitment

Security is a continuing engineering process, not a single “anti-hacker” switch. These browser and hosting settings reduce common risks but cannot stop every attack or protect data that has not yet been moved behind a secure backend.
